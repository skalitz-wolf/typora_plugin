# 演示文稿不提供源码视图

Deck 模式只有两栏：**编辑栏**（Typora 自己的编辑器）和**幻灯片栏**。没有源码视图，
也没有"显示 Markdown 原文"的按钮。

背景：最初的规格里有三个视图——源码 / 预览 / 分栏，其中"源码"指 Typora 自己的源码模式。
这条路走不通，而且不是审美问题：

- Typora 自己的规则 `.pin-outline:not(.typora-sourceview-on) #typora-sidebar{display:block}`
  会在源码模式下隐藏固定侧栏，文件树和大纲随之消失。
- 后来改成插件自绘的纯文本面板，又要额外发明一套双向同步（光标、撤销栈、谁先谁后），
  而 Typora 的文档模型是"DOM 即文档"，这类同步历来出诡异 bug。

**更关键的是：源码视图对导出毫无必要。** `File.editor.getMarkdown()` 在两种模式下都保真
（front matter 走 `meta_block.toMark()` 会重拼 `---` 围栏，HTML 注释走 `html_block` 原样
透传——见 ADR-0005）。既然拿文本不需要源码模式，这个视图就只剩"给用户看 Markdown 原文"
这一个用途，而 Typora 自带源码模式（`Ctrl+/`）已经能看。

去掉它带来的好处是连锁的：

- **不再切换 Typora 的任何模式**，侧栏永远在。
- **实时预览原生可用**。`fileEdited` 观察的是 `#write`，而 `#write` 就是默认模式下的编辑器
  （只在源码模式下被隐藏）。所以编辑文档就会触发事件，不需要任何变通或请求。
- 之前为"非源码模式拿不到原样文本"而加的那些机制——源码模式探测、按文档只问一次的提示、
  导出前先保存再读回——全部不再需要。

代价：想在 Markdown 原文里改演示文稿（比如手写 front matter）时，得用 Typora 自己的
源码模式（`Ctrl+/`）。这是有意为之——那是 Typora 的功能，不该由插件再实现一遍。
