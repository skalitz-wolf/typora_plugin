# 演示文稿的源码取自 Typora 源码模式的缓冲区

导出与实时预览读取的 Markdown，来自 Typora 源码模式（`File.editor.sourceView.cm.getValue()`）；
只有在源码模式不可用时，才退回读取磁盘上的文件。**不使用** `File.editor.getMarkdown()`。

背景：Marp 把 YAML front matter 和 HTML 注释当作**指令**读取，而 `getMarkdown()` 是
AST → Markdown 的再序列化，仓库里既没有测试也没有注释能保证它保真——仓库中确证会丢格式的
例子正是这条路径（`sidebar_enhance` / `right_outline` / `easy_modify` 都用 `node.toMark()`
重新拼接）。仓库里被当作「原样文本」对待的只有两处：源码模式的 `cm.getValue()`，以及直接读
文件。而直接读文件拿不到**未保存**的编辑。

因此：源码模式是唯一同时满足「保真」与「跟得上输入」的来源。这也顺带解决了实时预览的可行性
问题——`fileEdited` 只在源码模式下触发，所以分栏预览本来就必须让用户处于源码模式。

代价：演示文稿模式会把文档切到源码模式，用户在分栏里编辑的是 Markdown 源码而不是所见即所得
的渲染结果。这对演示文稿是可接受的（指令和分页本来就要在源码里看），但对普通笔记就不是，所以
该模式必须按文件显式开启，不能对所有 `.md` 生效。

另：导出时仍会先保存文档，但那只是替用户保存他自己的文件；即使保存失败，导出也继续使用源码
模式缓冲区里的内容——也就是屏幕上正在显示的内容。
