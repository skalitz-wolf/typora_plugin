# 自写 ZIP writer，而不是打包 zip 依赖

PPTX 打包所需的 ZIP 写入能力由仓库内约 200 行的 `plugin/marp/zip.js` 提供，而不是引入
`jszip` / `yazl` 之类的依赖再按约定 esbuild 打包进 `plugin/global/core/lib/`。

背景：仓库既有约定是「所有 NPM 依赖预打包进 lib/」，且已有 `extract-zip` / `yauzl` 用于
**读取** zip。但 PPTX 只需要 STORE 与 DEFLATE 两种方法，不需要 Zip64、不需要加密、不需要
流式写入——正好是最容易自己写对、也最容易测的那一小块。为此引入一个依赖，代价是新增一个
需要长期跟踪上游的 vendored 产物、改动构建配置，而收益仅是省下约 200 行代码。

代价与约束：

- CRC-32 必须自己实现，**不能用 `zlib.crc32`**——该 API 远晚于本项目 Node 12.14 的兼容底线。
- 输出必须**确定性**：不写时间戳（DOS 日期字段固定），条目保持调用方给定顺序。这既让测试
  可以断言字节，也让同一份 deck 重复构建得到相同的文件。
- 该 writer 是这一处需求的专用实现，不是通用 zip 库；遇到需要 Zip64 或加密的场景应换成
  成熟依赖，而不是继续扩写它。

这是一次对既有约定的**刻意偏离**，因此记录在案：未来读者看到「仓库里手写了一个 zip writer」
时，不必怀疑是遗漏了打包步骤。
